## What's next

**1. Work the audit's own suggested order, starting with I1 and I2 — both are mechanical, and I2 is quietly corrupting the project's single most valuable external check.**

The audit's issue I1: `validation.py` still computes line flux with the plain pixel sum (`flux_sum`), never updated when `measure.blue_red_side_ratio` got its Δλ fix on 09-17. Its own comments claim this "matches the bootstrap convention" — it doesn't, not anymore. The practical costs are concrete: `error_cross_check` reports a jackknife/bootstrap ratio of ≈5 when the two methods actually agree, the z-scramble null plot puts the bootstrap band 5× below the data, and `bootstrap_flux_profile`, `sweep_flux_window`, `gaussian_flux_window` all report amplitudes and luminosities 5× the main pipeline's. The fix is exactly the one already applied elsewhere: switch those calls to `flux_integral`.

I2 is the one that matters more. The Niemeyer 2022 comparison notebook (`2_Validate_Literature`) is set up with `flux_unit="flux_arcsec2"` and `rest_density=False` — which sums a per-*observed*-Å spectrum over *rest* Å, silently dividing the result by (1+z). The audit measured it directly: before the 09-17 fix this gave curves 1.5–1.7× too high; after the fix, the same setting now gives curves ~3× too low. `GOALS.md` §7 names this exact check — same instrument, same parent sample, independent reduction — as "**Tier 1 — external replication**... the single most valuable check in the suite; main text, not appendix." Right now that check is being run on the wrong quantity, and the direction of the error flipped under it three days after it was written, without anyone touching the notebook. Fix: `rest_density=True`.

Why now: both are one-line changes in a fresh, itemized audit, and I2 specifically is the difference between a real Tier-1 validation and an artifact of a stale keyword argument. What it unblocks: a trustworthy external-replication paragraph for Paper I's Results section, and correct internal error diagnostics for every split that calls `variance_budget`.

**Recent:**

1. **Zhang 2026** — A General Framework for Radial Velocity Calibration in Low-Resolution Spectroscopic Surveys: Correcting Wavelength-Dependent and Global Systematics with Application to LAMOST DR9 (arXiv:2604.19119, April 2026). Splits LAMOST spectra into eight wavelength segments to isolate wavelength-dependent velocity offsets, then applies spectrograph- and fiber-level zero-point corrections anchored to APOGEE and Gaia RVS repeat observations, cutting cross-night scatter from ~3.6 to ~1.8 km/s. This is a different instrument and resolution regime, but the shape of the problem is exactly `specs/wavelength-zero-point.md`'s: a wavelength-dependent piece (their eight segments; VDFI's leading air/vacuum hypothesis is flat across the band, which this framework's segment-by-segment diagnostic would either confirm or contradict directly) plus a global zero-point tied down with external, non-line, non-target radial velocities (their APOGEE/Gaia anchor; VDFI's own plan already calls for Gaia-anchored stellar RVs, Tier 2, promoted). Worth reading as a template for the Tier-0 convention audit that has sat at "nothing executed" for 60 days — it is a worked example of the exact two-stage correction this project has already scoped but not built.

2. **Gámez Rosas 2026** — STARSFLUX: an all-sky catalogue of absolute spectro-photometric calibrators from 0.3 to 30 μm (arXiv:2607.11730, July 2026). Builds ~65,000 synthetic stellar spectra spanning UV through mid-IR by fitting Gaia DR3 parameters and multi-band photometry to NewEra PHOENIX atmosphere models, yielding absolutely calibrated synthetic photometry in arbitrary passbands. Directly operational for recommendation 3: `flux_scale_check` currently synthesizes one PS1 g magnitude per star; a catalogue like this would let the same check be run in several bands across the VIRUS range from a single, internally consistent stellar model rather than cross-matching against PS1 DR2 band by band, which turns a single R value into a wavelength-dependent throughput check — the same upgrade last week's Xiao 2026 (BEST) suggested, via an independent construction (synthetic spectra from stellar atmosphere models rather than re-calibrated Gaia XP spectrophotometry). Worth comparing the two before committing to either as the reference photometry.

3. **Le Reste 2025** — The Lyman-alpha and Continuum Origins Survey. I. Survey description and Lyα imaging (arXiv:2504.07056, April 2025). Describes LaCOS, an HST imaging survey of 42 Low-redshift Lyman Continuum Survey galaxies (22 confirmed LyC emitters, f_esc(LyC) 0.01–0.49) across 5 filters spanning rest-UV to rest-optical, with Lyα imaging finding that correlations with LyC escape strengthen when measured in small apertures around the brightest UV clumps. This is the survey-description paper behind **Saldana-Lopez 2026 (LaCOS II)**, already in `docs/literature/` — the companion paper describing the actual imaging methodology was not. Directly relevant to `GOALS.md` §6 (Paper III's absolute f_esc): it is a second, independent group building the same core/aperture-dependent escape-fraction picture VDFI is building, on a lower-redshift but methodologically comparable sample, and the "small aperture strengthens the correlation" finding is a real-data instance of the same core-vs-halo partition question in recommendation 3 and the audit's I6.

**Older, likely not yet reviewed:**

4. **Garate-Nuñez 2025** — Correcting for the effects of the point spread function in intra-halo light measurements and application to deep Hyper Suprime-Cam data (arXiv:2505.24395, May 2025). Shows that fitting an exponential intra-halo-light (IHL) model to deep group images without a PSF-scattering correction overestimates the true diffuse flux by up to 100×, and develops an MCMC-fit PSF correction validated on mock group observations before applying it to real HSC data. This is the imaging-domain version of the audit's **I6**: a compact/point-source term convolved with a broad PSF can masquerade as extended diffuse light (or vice versa) unless the model explicitly separates the two, which is precisely the objection `TODO.md`'s 09-25 entry raises against treating the 0–10 kpc bin as a point-source aperture correction when the fitted profile has no point-source term. Different domain (broadband group imaging vs. stacked narrowband spectroscopy), same statistical trap, and a published, validated correction method for it.

5. **Mohammad 2022** — Creating jackknife and bootstrap estimates of the covariance matrix for the two-point correlation function (arXiv:2109.07071, September 2021; MNRAS 514, 1289). Derives correction terms that let delete-one jackknife and bootstrap recover unbiased covariance estimates for correlation-function-like statistics, via a weighting scheme (v_match) that properly accounts for auto- and cross-pair contributions, validated to ~10% against 1000 QUIJOTE simulations. Relevant to the project's oldest standing blocker: `bin-correlation-diagnostics.md` (65 days) and the audit's own framing of why the current bootstrap can't see the correlated background — "resampling galaxies cannot see a background common to all of them" — is exactly the failure mode this paper's correction terms are built to fix. It is a two-point-correlation-function method, not a direct drop-in, but the underlying problem (a resampling scheme blind to a shared, non-galaxy-indexed term) is the same one, and it is a candidate method for making the random-position nulls (`TODO.md`) more than an ad hoc check — a corrected covariance estimator with error bars behind the correction itself.
